# Orbi × OpenCode

**Approvals + status.** Orbi → Settings → Integrations → OpenCode → Connect
writes one generated plugin, `~/.config/opencode/plugins/orbi.js`. It starts
with a "Generated by Orbi (orbi-hook)" line. Orbi never touches an `orbi.js`
without that line. Disconnect deletes the file. Restart OpenCode to load it.

How it works (https://opencode.ai/docs/plugins/):

- **Approvals:** OpenCode's typed `permission.ask` plugin hook is never
  called in current releases (issues #7006, #47674), so the plugin listens for
  the `permission.asked` event. It runs `orbi-hook ask --agent opencode` with
  `{cwd, request}` on stdin, which prints `allow` / `deny` / `ask`. Then it
  replies through OpenCode's API: `client.permission.reply({requestID, reply: "once"|"reject"})`,
  or the older `POST /session/:id/permissions/:permissionID`. On `ask` it does
  nothing, and OpenCode's own prompt, which stays up the whole time, decides.
  If you answer in OpenCode first, the `permission.replied` event cancels
  Orbi's pending request.
- **Status:** `tool.execute.before` → "running `…`" / "editing `…`";
  `session.status` busy → "is thinking…"; `session.idle` → "finished";
  `session.error` → "stopped with an error".
- If Orbi.app is gone, the plugin checks that the hook is executable first and
  does nothing if not.
